**프로젝트명:** CODI-IT – 패션 이커머스 플랫폼  
**팀명:** 2팀  
**작성자:** 권나현  
**작성일:** 2025.10.26  
 
## 1. 프로젝트 개요

### 1-1. 프로젝트기간 : 09월 15일 ~ 11월 03일

### 1-2. 목적:
- 패션 이커머스 환경에서 판매자와 구매자가 효율적으로 소통하고 거래할 수 있는 통합 플랫폼 입니다. 
- 상품 관리부터 주문·결제·리뷰까지의 전 과정을 자동화하여 편리하고 안정적인 쇼핑 경험을 제공하는 서비스입니다.

### 1-3. 주요 기능:
| 모듈 | 주요 기능 |
|:------|:-----------|
| **S3 (이미지 업로드)** | 상품·스토어 이미지 업로드 지원 |
| **Auth (인증/인가)** | JWT 인증 + Refresh 토큰 쿠키 회전 |
| **User (회원)** | 회원가입/내 정보 조회·수정·탈퇴, 관심 스토어 조회 |
| **Store (스토어)** | 스토어 등록/수정/조회, 내 스토어 상세 조회, 등록 상품 조회, 관심 스토어 등록/해제 |
| **Product (상품)** | 상품 등록/목록/상세/수정/삭제, 상품 문의 등록/조회 |
| **Cart (장바구니)** | 생성/조회/수정(추가·수량)/아이템 상세·삭제 |
| **Orders (주문)** | 주문 생성/목록(페이지네이션)/상세/취소/정보 수정 |
| **Review (리뷰)** | 상품 리뷰 작성/목록/상세/수정/삭제 |
| **Inquiry (문의/답변)** | 내 문의 조회/상세/수정/삭제, 답변 상세 조회/수정/등록 |
| **Dashboard / Alarm / Metadata** | 판매·주문 지표, 알림, 메타데이터 관리 |

## 2. 주요 개발 내역

### 백엔드 (Express + Prisma)
- Prisma ORM을 활용한 DB 모델(Auth, User, Point) 설계 및 마이그레이션
- 구현 기능
   - Auth 모듈: 로그인, 리프레시 토큰 재발급, 로그아웃
   - User 모듈: 회원가입, 내 정보 조회 및 수정, 관심 스토어 조회, 회원 탈퇴
   - Point 모듈: 내 포인트 조회
   - Grade 모듈: 내 등급 조회
   - 전역 로깅 미들웨어: 요청(Request)과 응답(Response) 정보를 콘솔에 출력하도록 구현
- 테스트 및 검증
   - Auth, User, Point, Grade 모듈의 유닛 테스트 코드 작성
   - 주요 기능 동작 및 예외 처리 검증을 통해 안정성 확보
- 협업 및 관리
   - 이슈 템플릿, PR 템플릿 제작으로 협업 효율화
   - Wiki 문서 작성을 통한 프로젝트 구조 및 기능 명세 정리
- 기타 작업
   - User 프로필 사진 생성 기능 구현
   - 중간·최종 발표용 PPT 제작 및 구성 참여

### 프론트엔드/테스트
- Postman을 이용한 백엔드 API 단위 테스트 및 통합 테스트
- 프론트 연동 후 수정 

## 3. 개발 이슈 및 해결 내역
| **이슈명**                          | **발생 원인 및 내용**                                                                                             | **해결 방법 및 결과**                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **Express → Nest 전환 과정의 구조적 혼란** | 기존 Express 프로젝트에서는 라우터 중심의 단순 구조로 동작했지만, Nest.js는 모듈·서비스·컨트롤러 구조를 사용하여 코드 책임이 분리되어 초기 구조 설계에 혼란이 발생함.      | Nest의 **의존성 주입(DI)** 개념과 **모듈화 구조**를 학습하고, `Service`와 `Repository`의 역할을 명확히 구분하여 프로젝트 구조를 재정비함. 그 결과 코드의 재사용성과 유지보수성이 크게 향상됨.            |
| **JWT 타입 에러 및 쿠키 설정 개선**         | `jsonwebtoken` 사용 시 토큰 검증 후 사용자 타입이 명확히 지정되지 않아 타입 오류 발생. 또한 쿠키에 토큰 저장 시 CORS 및 Secure 옵션 문제로 인증 실패 이슈 발생. | `AuthUser` 인터페이스를 정의해 타입 안정성을 확보하고, Nest의 `cookie-parser`와 환경변수 기반 쿠키 설정(`sameSite`, `secure`)을 적용하여 문제 해결. 브라우저 환경에서도 정상적으로 인증 흐름이 작동됨. |
| **단위 테스트 환경에서의 Prisma Mock**     | 유닛 테스트 작성 시 실제 DB 접근으로 인해 테스트가 느려지고 독립성이 떨어짐. `PrismaService` 의존성 주입으로 인해 테스트 환경 분리가 어려웠음.                 | Jest 환경에서 **Prisma Mock 객체**를 생성하고 `overrideProvider()`로 주입하여 실제 DB 의존성을 제거. 각 서비스 단위 테스트에서 독립적인 검증이 가능해졌으며, 테스트 속도와 안정성이 향상됨.           |
