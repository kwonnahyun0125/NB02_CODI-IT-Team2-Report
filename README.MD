## 1. 프로젝트 개요

### 1-1. 프로젝트기간 : 09월 15일 ~ 11월 03일

### 1-2. 목적:
- 패션 이커머스 환경에서 판매자와 구매자가 효율적으로 소통하고 거래할 수 있는 통합 플랫폼 입니다. 
- 상품 관리부터 주문·결제·리뷰까지의 전 과정을 자동화하여 편리하고 안정적인 쇼핑 경험을 제공하는 서비스입니다.

### 1-3. 주요 기능:
| 모듈 | 주요 기능 |
|:------|:-----------|
| **S3 (이미지 업로드)** | 상품·스토어 이미지 업로드 지원 |
| **Auth (인증/인가)** | JWT 인증 + Refresh 토큰 쿠키 회전 |
| **User (회원)** | 회원가입/내 정보 조회·수정·탈퇴, 관심 스토어 조회 |
| **Store (스토어)** | 스토어 등록/수정/조회, 내 스토어 상세 조회, 등록 상품 조회, 관심 스토어 등록/해제 |
| **Product (상품)** | 상품 등록/목록/상세/수정/삭제, 상품 문의 등록/조회 |
| **Cart (장바구니)** | 생성/조회/수정(추가·수량)/아이템 상세·삭제 |
| **Orders (주문)** | 주문 생성/목록(페이지네이션)/상세/취소/정보 수정 |
| **Review (리뷰)** | 상품 리뷰 작성/목록/상세/수정/삭제 |
| **Inquiry (문의/답변)** | 내 문의 조회/상세/수정/삭제, 답변 상세 조회/수정/등록 |
| **Dashboard / Alarm / Metadata** | 판매·주문 지표, 알림, 메타데이터 관리 |

## 2. 주요 개발 내역

### 백엔드 (Express + Prisma)
- Prisma ORM을 활용한 DB 모델(Auth, User, Point) 설계 및 마이그레이션
- 구현 기능
   - Auth 모듈: 로그인, 리프레시 토큰 재발급, 로그아웃
   - User 모듈: 회원가입, 내 정보 조회 및 수정, 관심 스토어 조회, 회원 탈퇴
   - Point 모듈: 내 포인트 조회
   - Grade 모듈: 내 등급 조회
   - 전역 로깅 미들웨어: 요청(Request)과 응답(Response) 정보를 콘솔에 출력하도록 구현
- 테스트 및 검증
   - Auth, User, Point, Grade 모듈의 유닛 테스트 코드 작성
   - 주요 기능 동작 및 예외 처리 검증을 통해 안정성 확보
- 협업 및 관리
   - 이슈 템플릿, PR 템플릿 제작으로 협업 효율화
   - Wiki 문서 작성을 통한 프로젝트 구조 및 기능 명세 정리
- 기타 작업
   - User 프로필 사진 생성 기능 구현
   - 중간·최종 발표용 PPT 제작 및 구성 참여

### 프론트엔드/테스트
- Postman을 이용한 백엔드 API 단위 테스트 및 통합 테스트
- 프론트 연동 후 수정

## 4. 구체적 개발 예시
### 1) JWT 인증 & 리프레시 토큰 재발급 흐름 정비
- 상황: 로그인 후 일정 시간 지나면 401이 빈번 발생, 환경별 쿠키 정책 불일치로 토큰 전달 실패.
- 목표: 안정적인 인증 유지와 보안 준수(HTTP-only 쿠키, CORS 호환).
- 접근/핵심 결정:
   - accessToken 단기(예: 15m), refreshToken 장기(예: 7d) 전략.
   - cookie.util.ts에서 환경별 분기: Dev(sameSite:lax, secure:false) / Prod(sameSite:none, secure:true), 공통 path:'/'.
   - JwtSignOptions['expiresIn'] 타입 단언으로 문자열 포맷 허용, signAsync 중복 옵션 제거.
- 결과: 인증 만료/쿠키 전송 이슈 해소, 재발급 루틴 정상화로 이탈률 감소.

### 2) 전역 로깅 미들웨어로 요청/응답 가시성 확보
- 상황: 장애 시 원인 추적 어려움, 엔드포인트별 소요 시간 파악 불가.
- 목표: 요청/응답 로깅, 성능 병목 지점 파악, 민감정보 마스킹.
- 접근/핵심 결정:
   - 전역 미들웨어에서 method, url, status, duration(ms), userId 로깅.
   - Authorization, 쿠키, 비밀번호 등 민감 필드 마스킹.
   - 오류 스택은 레벨 분리(정보/경고/에러).
- 결과: 병목 API와 예외 패턴이 명확해져 디버깅 시간 단축.

### 3) Express 스타일 → Nest 관심사 분리(Guard/Pipe/Interceptor) 재구성
- 상황: 인증·검증·응답 포맷팅이 Interceptor에 혼재되어 사이드이펙트 발생.
- 목표: 각 단계의 책임 분리로 예측 가능한 동작 보장.
- 접근/핵심 결정:
   - 인증은 Guard, 요청 DTO 검증은 Pipe, 공통 응답 포맷/트랜스포밍은 Interceptor, 비즈니스는 Service/Repository로 재배치.
- 결과: 코드 가독성/테스트 용이성 향상, 회귀 버그 감소.

### 4) Prisma Repository 분리 & 테스트 가능한 서비스 계층
- 상황: 서비스가 Prisma에 직접 의존해 단위 테스트가 DB 연결에 막힘.
- 목표: DB 독립적인 서비스 테스트 환경 구성.
- 접근/핵심 결정:
   - UsersRepository, AuthRepository 등 Repository 계층 도입.
   - 서비스는 Repository 인터페이스만 의존하도록 리팩터링.
- 결과: Jest에서 Prisma Mock 주입이 가능해져 빠르고 독립적인 단위 테스트 확보.

### 5) 단위 테스트: 성공/실패 시나리오 중심 검증
- 상황: 기존엔 Postman 수동 검증만으로 회귀 이슈 빈발.
- 목표: 주요 경로(성공/예외) 자동 검증으로 안정성 확보.
- 접근/핵심 결정:
   - Auth: 정상 로그인, 비밀번호 불일치, 탈퇴 유저, 토큰 만료 재발급 실패.
   - User: 내 정보 조회/수정, 권한 불일치, 유효성 예외.
   - Repository 함수들을 jest.fn()으로 Mock, 입력/출력/예외를 시나리오화.
- 결과: 핵심 로직 회귀 방지, 릴리즈 전 신뢰도 상승.

### 6) 프로필 이미지 업로드(안전성·일관성)
- 상황: 확장자/용량 제한 부재, 경로 표준화 미흡.
- 목표: 안전한 업로드와 일관된 URL 제공.
- 접근/핵심 결정:
   - 파일 확장자·용량 제한, 파일명 충돌 방지(UUID), 저장 경로 규칙화.
   - 응답에 공개 URL/상대 경로 일관 제공, 실패 시 원자적 롤백.
- 결과: 업로드 오류/보안 리스크 감소, FE 연동 단순화.

### 7) 포인트/등급 조회 API의 단일 책임화
- 상황: 포인트 합산·등급 계산 로직이 여러 곳에 중복.
- 목표: 계산 기준 단일화로 유지보수 비용 절감.
- 접근/핵심 결정:
   - PointService에서 적립/차감/합산 규칙 단일화.
   - GradeService에서 GRADE_MAP기반 등급 판정 규칙 캡슐화.
- 결과: 비즈니스 규칙 변경 시 영향 범위 최소화, 테스트 범위 명확.

### 8) 협업 생산성: 이슈/PR 템플릿 & Wiki
- 상황: 이슈·PR 품질 편차로 리뷰 효율 저하.
- 목표: 공통 서식으로 의사소통 비용 절감.
- 접근/핵심 결정:
   - 이슈 템플릿: 배경/요구사항/작업/체크리스트.
   - PR 템플릿: 요약/변경사항/추가설명/관련 이슈/체크리스트.
   - Wiki: 아키텍처 다이어그램, 모듈 책임, 로깅/쿠키 정책, 실행 가이드 정리.
- 결과: 리뷰 리드타임 단축, 온보딩 시간 감소.

## 5. 성과 및 배운 점
이번 고급 프로젝트에서는 기존에 익숙했던 Express 대신 Nest.js를 처음으로 적용하며 새로운 프레임워크의 구조와 철학을 직접 경험할 수 있었습니다.
Nest의 모듈화, 의존성 주입(DI), 데코레이터 기반 설계를 익히며 대규모 애플리케이션에서의 구조적 개발 방식을 이해하게 되었습니다.

또한 **인증/인가 로직(JWT 기반 로그인, 토큰 재발급, 로그아웃 등)**을 처음으로 직접 구현하면서 보안 처리와 세션 관리의 중요성을 배웠습니다.
이전 프로젝트에서는 Postman을 통해 단순 요청 검증만 했지만, 이번에는 **단위 테스트(Unit Test)**를 적용하여 기능 단위로 안정성을 검증하는 과정을 경험했습니다.

초급·중급 프로젝트를 거치며 다양한 문제를 해결했던 경험이 이번 프로젝트에서 큰 도움이 되었고,
이제는 전체적인 흐름을 파악하며 불필요한 코드 수정 없이 효율적으로 문제를 해결할 수 있게 되었다는 점에서 스스로의 성장을 느꼈습니다.

마지막으로, 팀원들과의 꾸준한 협업과 소통을 통해 기간 내에 프로젝트를 완성할 수 있었고,
결과물 또한 높은 완성도를 보여 만족스러웠습니다.

특히 실무에서도 널리 사용되는 Nest.js를 기반으로 프로젝트를 완성했다는 점이 큰 의미 있는 성과라고 생각합니다.

## 6. 향후 과제 및 개선 방향
이번 프로젝트를 통해 Nest.js의 구조와 백엔드 전반의 흐름을 이해했지만, 아직 아키텍처 설계와 테스트 코드의 깊이 있는 활용에는 보완이 필요하다고 느꼈습니다.
앞으로는 테스트 커버리지 확장과 예외 상황 처리 강화를 통해 안정적인 서버 운영이 가능하도록 개선할 계획입니다.

또한 현재는 단일 서버 구조로 되어 있지만, 향후에는 모듈 간 의존성 최소화 및 마이크로서비스 구조(MSA) 설계에 도전해보고 싶습니다.
이를 통해 유지보수성과 확장성을 높이고, 실제 서비스 환경과 유사한 시스템을 구축하는 것이 목표입니다.

프론트엔드와의 통신 과정에서도 더 나은 사용자 경험을 제공하기 위해 API 응답 구조 표준화와 성능 최적화를 진행할 예정입니다.
마지막으로, 협업 과정에서 배운 점을 바탕으로 문서화와 코드 리뷰 문화를 꾸준히 강화하여, 팀 전체의 개발 효율성과 코드 품질을 높이는 방향으로 나아가고자 합니다.
